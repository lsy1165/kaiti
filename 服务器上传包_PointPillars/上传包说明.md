# PointPillars 服务器运行说明

本说明用于指导在 GPU 服务器上运行单模态三维目标检测展示。

当前任务只做检测展示：

```text
多帧点云 demo -> PointPillars 预训练模型 -> BEV 检测图和检测结果文件
```

当前阶段不训练模型，不需要完整 KITTI 数据集。

## 第 1 步：确认上传包内容

上传到服务器的是整个文件夹：

```text
服务器上传包_PointPillars/
```

上传包内主要内容如下：

```text
服务器上传包_PointPillars/
├── code/server_pointpillars/                         # 服务器运行脚本
├── code/data/stage02_mono3d_detection/demo_samples/  # demo 点云
└── code/models/openpcdet/pointpillar_kitti.pth       # PointPillars 预训练权重
```

`demo_samples/` 里有 1 个基础点云和 8 个展示用变体，共 9 个 `.bin` 点云文件。变体只用于生成更多展示图，不作为正式实验数据。

## 第 2 步：进入上传包根目录

如果你用的是 AutoDL/root 容器，通常执行：

```bash
cd /root/服务器上传包_PointPillars
```

也可以执行：

```bash
cd ~/服务器上传包_PointPillars
```

如果终端提示符已经类似下面这样，说明已经在上传包根目录：

```text
root@...:~/服务器上传包_PointPillars#
```

这种情况下不需要再执行 `cd`。

## 第 3 步：不要再创建新的 conda 环境

如果之前运行过下面这个脚本并卡住：

```bash
bash code/server_pointpillars/01_create_conda_env.sh
```

看到类似：

```text
Collecting package metadata
Solving environment
```

先按：

```bash
Ctrl + C
```

停止它。

后面不要再运行：

```bash
bash code/server_pointpillars/01_create_conda_env.sh
bash code/server_pointpillars/08_quick_demo_only.sh
```

原因是这两个流程会尝试新建 `kaiti3d` 环境，conda 解析依赖很慢。现在改用服务器镜像自带的 PyTorch/base 环境。

## 第 4 步：激活服务器自带 base 环境

先让当前终端支持 `conda activate`：

```bash
eval "$(conda shell.bash hook)"
```

然后设置脚本使用 `base` 环境：

```bash
export CONDA_ENV_NAME=base
conda activate base
```

如果 `eval "$(conda shell.bash hook)"` 报错，就改用：

```bash
source /root/miniconda3/etc/profile.d/conda.sh
export CONDA_ENV_NAME=base
conda activate base
```

成功后，命令行前面通常会出现：

```text
(base)
```

## 第 5 步：检查 GPU 和 PyTorch

执行：

```bash
python - <<'PY'
import torch
print("torch:", torch.__version__)
print("cuda available:", torch.cuda.is_available())
print("cuda:", torch.version.cuda)
print("gpu count:", torch.cuda.device_count())
if torch.cuda.is_available():
    print("gpu:", torch.cuda.get_device_name(0))
PY
```

这里必须看到：

```text
cuda available: True
gpu count: 1
```

如果 `cuda available` 是 `False`，先停下来，把截图发给我。

## 第 6 步：安装基础依赖

执行：

```bash
python -m pip install -U pip wheel
python -m pip install --force-reinstall "setuptools==68.2.2" "numpy==1.26.4"
python -m pip install pyyaml easydict tqdm tensorboardX scikit-image SharedArray matplotlib pyquaternion "opencv-python<4.10" "numba<0.60" spconv-cu118
```

如果这一行报 `spconv-cu118` 相关错误，把报错截图发给我。

如果你之前已经看到 `numpy 2.2.6` 或 `No module named 'pkg_resources'` 报错，也从本步重新执行。执行完后继续第 7 步。

## 第 7 步：安装 OpenPCDet

执行：

```bash
bash code/server_pointpillars/02_install_openpcdet.sh
```

这一步会把 OpenPCDet 下载到：

```text
external/OpenPCDet/
```

并执行安装。正常情况下可能需要几分钟。

## 第 8 步：检查 demo 点云和预训练权重

执行：

```bash
bash code/server_pointpillars/03_prepare_demo_assets.sh
```

这一步会检查：

```text
code/data/stage02_mono3d_detection/demo_samples/
code/models/openpcdet/pointpillar_kitti.pth
```

如果文件都在，通常很快完成。

## 第 9 步：运行 PointPillars 检测展示

执行：

```bash
bash code/server_pointpillars/05_run_pointpillar_demo.sh
```

这一步会对 `demo_samples/` 里的多帧点云进行检测，并生成 BEV 检测图。

如果这里报：

```text
ModuleNotFoundError: No module named 'av2'
```

说明 OpenPCDet 最新代码导入了 Argo2 数据集的可选依赖。当前 demo 只跑 KITTI/PointPillars，不需要 Argo2。执行下面命令跳过这个可选导入：

```bash
python - <<'PY'
from pathlib import Path

p = Path("external/OpenPCDet/pcdet/datasets/__init__.py")
s = p.read_text(encoding="utf-8")
s = s.replace(
    "from .argo2.argo2_dataset import Argo2Dataset",
    "try:\\n    from .argo2.argo2_dataset import Argo2Dataset\\nexcept ModuleNotFoundError:\\n    Argo2Dataset = None",
)
s = s.replace(
    "    'Argo2Dataset': Argo2Dataset\\n}",
    "    **({'Argo2Dataset': Argo2Dataset} if Argo2Dataset is not None else {})\\n}",
)
p.write_text(s, encoding="utf-8")
PY
```

然后重新执行第 9 步。

如果这里报：

```text
FileNotFoundError: cfgs/dataset_configs/kitti_dataset.yaml
```

说明脚本没有在 OpenPCDet 的 `tools` 目录下读取配置。执行下面命令修复：

```bash
python - <<'PY'
from pathlib import Path

p = Path("code/server_pointpillars/tools/run_openpcdet_inference.py")
s = p.read_text(encoding="utf-8")
if "import os\n" not in s:
    s = s.replace("import math\n", "import math\nimport os\n")
old = "    args = parse_args()\\n    add_openpcdet_to_path(args.openpcdet_dir)\\n    patch_openpcdet_optional_dataset_imports(args.openpcdet_dir)\\n"
new = """    args = parse_args()
    args.openpcdet_dir = args.openpcdet_dir.resolve()
    args.cfg_file = args.cfg_file.resolve()
    args.ckpt = args.ckpt.resolve()
    args.data_path = args.data_path.resolve()
    args.output_dir = args.output_dir.resolve()

    add_openpcdet_to_path(args.openpcdet_dir)
    patch_openpcdet_optional_dataset_imports(args.openpcdet_dir)
    os.chdir(args.openpcdet_dir / "tools")
"""
if old in s:
    s = s.replace(old, new)
elif "os.chdir(args.openpcdet_dir / \"tools\")" not in s:
    raise SystemExit("Did not find the expected insertion point. Send the current error to Codex.")
p.write_text(s, encoding="utf-8")
PY
```

然后执行：

```bash
python -m py_compile code/server_pointpillars/tools/run_openpcdet_inference.py
bash code/server_pointpillars/05_run_pointpillar_demo.sh
```

## 第 10 步：确认服务器输出结果

运行完成后，执行：

```bash
ls code/outputs/server_pointpillars_demo
```

正常情况下会看到：

```text
predictions.json
000008_pred_bev.png
000008_backward_pred_bev.png
000008_forward_pred_bev.png
000008_forward_left_pred_bev.png
000008_forward_right_pred_bev.png
000008_near_left_pred_bev.png
000008_near_right_pred_bev.png
000008_shift_left_pred_bev.png
000008_shift_right_pred_bev.png
inference.log
```

只要这里出现多张 `*_pred_bev.png`，就说明单模态三维目标检测展示已经跑通。

## 第 11 步：把结果复制回本机

服务器结果目录是：

```text
/root/服务器上传包_PointPillars/code/outputs/server_pointpillars_demo/
```

把整个 `server_pointpillars_demo` 文件夹复制回本机：

```text
E:\kaiti\code\outputs\
```

复制完成后，本机最终应该是：

```text
E:\kaiti\code\outputs\server_pointpillars_demo\
```

结果文件含义：

```text
*_pred_bev.png    # 检测展示图
predictions.json  # 检测框、类别、置信度
inference.log     # 运行日志
```

## 第 12 步：保存服务器镜像

确认第 10 步已经生成检测图，并且第 11 步已经把结果复制回本机后，再在租用平台页面保存服务器镜像。

没有跑通前先不要保存镜像。
