# 多样例一对一复杂工况方案

## 思路

多模态基础系统展示只保留阶段 3 已跑通的 `000008` 一帧，用于说明 MVX-Net 图像+雷达多模态三维检测流程能够正常运行。

复杂工况阶段不采用“同一帧生成多种复杂工况”的方式，而采用“多个原始样例分别对应一种复杂工况”的方式。这样展示时不会显得所有结果都来自同一帧，逻辑更接近正式实验。

## 一对一规则

当前实际对应关系如下：

```text
原始样例 000008 -> 弱光
原始样例 000021 -> 雾天
原始样例 000022 -> 运动模糊
原始样例 000023 -> 图像噪声
原始样例 000024 -> 点云稀疏
原始样例 000025 -> 点云扰动
```

每个原始样例最多生成一个复杂工况样例。

## 数据保存结构

为了便于展示改变前和改变后的对比，生成脚本会同时保存两种结构。

第一种是平铺的复杂工况样例目录：

```text
code/data/stage04_complex_conditions/condition_samples/
```

该目录主要用于快速查看所有复杂工况文件。

第二种是推荐用于展示和服务器检测的成组目录：

```text
code/data/stage04_complex_conditions/paired_samples/
  对比组ID/
    clean/
      原始样例.png
      原始样例.bin
      原始样例.pkl
    complex/
      复杂工况样例.png
      复杂工况样例.bin
      复杂工况样例.pkl
    pair_info.json
```

其中 `clean/` 是改变前数据，`complex/` 是改变后数据。后续检测结果也按这个结构保存。
